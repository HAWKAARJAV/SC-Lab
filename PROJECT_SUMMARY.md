# Project summary: hard vs fuzzy eye-tracking gating for fuzzy EEG classification (ZuCo 1.0)

> **Superseded:** the complete final report, which covers ZuCo **and SEED-IV**, is [`FINAL_REPORT.md`](FINAL_REPORT.md) (PDF: `manuscript/final_project_report/main.pdf`). This file keeps the detailed ZuCo-only write-up.

Everything about the project is in this one file: goal, method, data, the defects we found and fixed, all results, conclusions, and how to reproduce them. The full write-up is `manuscript/zuco_report/main.pdf`.

---

## 1. One-paragraph summary

We re-implemented the eye-gated EEG emotion-recognition method of Farhadi Sedehi et al. (IEEE Access 2024). The pipeline is: wavelet-band entropy features → mRMR feature selection → a Sugeno fuzzy classifier whose rules are tuned by a genetic algorithm. An eye-tracking gate decides which EEG windows to trust. The paper's gate is a **hard** pupil threshold (**M0**). We propose softer gates: **M1**, a fuzzy Low/Medium/High pupil gate, and **M2**, an adaptive, temporally smoothed fuzzy gate. We also test **M1 + temporal** (M1 with M2's smoothing). SEED-IV and MAHNOB-HCI require signed licences, so we evaluated on the free **ZuCo 1.0** dataset: 12 people, 4,430 sentences, real EEG plus eye tracking, labelled negative, neutral or positive.

**Results.** After fixing five real pipeline defects, every model is at chance (about 33%; chance is 33.3%). The proposed gates are 0.2–0.5 points ahead of M0 under 5-fold cross-validation and 0.2–0.6 points behind it when testing on unseen people. No difference is significant. Even a plain logistic regression on all features reaches only about 35%, so ZuCo carries almost no sentiment signal in these features, and **no gate can show a benefit on it**. The fair test of M1 and M2 needs an induced-emotion dataset such as SEED-IV.

## 2. Models compared (only the eye gate differs)

| Name | What the gate does |
|---|---|
| **No gate** | Every 1-s window has weight 1 (reference). |
| **M0: hard gate (paper)** | Keeps a window (weight 1) if its pupil value is in the top 40% of its sentence; otherwise weight 0. |
| **M1: fuzzy gate (proposed)** | Pupil size is scaled against **each person's own range**, then Low/Medium/High fuzzy memberships (breakpoints 0.2/0.5/0.8) give a weight of 0.1/0.5/1.0. Every window is kept, with a graded weight. |
| M1 v1 (ablation) | Same as M1, but pupil size is scaled **within each sentence**. This was our first version and turned out to be degenerate (see §5). |
| **M2: adaptive temporal gate (proposed)** | Like M1, but each person's Low/Medium/High breakpoints sit at **their own** 20th/50th/80th pupil percentiles (adaptive), and weights are **smoothed over neighbouring windows** (temporal: t−1, t, t+1). |
| M2 adaptive-only | M2 without the smoothing. |
| M2 causal | M2 smoothing over past windows only (t−1, t), so it could run in real time. |
| **M1 + temporal** | M1 (fixed breakpoints) plus M2's temporal smoothing. |

The old M3 (multi-band fusion) and M4 (M2 + M3) were removed from the project.

All gates are **label-free**: they only look at the eye signal, never at the answer. Gate weights enter every training step (feature selection, membership functions, rule generation, GA fitness) and the final vote over a sentence's windows.

## 3. Pipeline (shared by every model)

1. **EEG preprocessing:** 1–60 Hz band-pass (4th-order Butterworth) and 50 Hz notch, applied to each continuous ~4-minute block before cutting sentences (avoids edge artefacts), then resampled to 128 Hz.
2. **Bands:** a 4-level db4 wavelet gives delta 0–4, theta 4–8, alpha 8–16, beta 16–32 and gamma 32–64 Hz.
3. **Windows:** non-overlapping 1-s windows (sentences are short).
4. **EEG features per window, band and channel:** sample entropy (SampEn, m=2), permutation entropy (m=3, τ=1), symbolic dynamic entropy (m=3, τ=1) and phase entropy. Each is z-scored within each person.
5. **Eye features per window:** fixation duration (mean, SD, max), fixation rate, and pupil diameter (mean, SD). The gate uses the top eye feature by mRMR on the training data. That was **mean pupil diameter in every fold**.
6. **Classifier:** weighted mRMR picks 3 EEG features, which feed a Sugeno fuzzy system with 3 membership functions per input (27 rule cells). Rules are generated by weighted Wang–Mendel, then a GA (population 27, early stopping) selects and edits them.
7. **Decision:** one prediction per sentence, the gate-weighted average of window probabilities.
8. **Class balance:** training windows are weighted by inverse class frequency, and the GA optimises balanced accuracy.

## 4. Data: ZuCo 1.0, task 1 (sentiment reading)

- **Download:** all 220 files (5.97 GB) for 12 participants, verified complete (`scripts/download_zuco.py`, 6 parallel downloads).
- **EEG:** EGI HydroCel 128-net at 500 Hz (105 channels after the dataset's cleaning). We use **19 channels** at approximate 10–20 positions: Fp1, Fp2, F7, F3, Fz, F4, F8, T7, C3, C4, T8, P7, P3, Pz, P4, P8, O1, Oz, O2.
- **Eye tracking:** EyeLink at 500 Hz. Pupil diameter = √(pupil area), with blinks treated as missing; fixations come from the EyeLink events.
- **Trials:** **one sentence = one trial**, using the onset/offset markers (10/11 normal, 12/13 control sentences). The 400 sentences are shown in a fixed order, so marker k corresponds to sentence k in the label file. We verified this: all 46 control markers land exactly on the control sentences. Five label rows broken by a `;` inside the sentence text were repaired.
- **Size:** **4,430 sentences** (negative 1,365 · neutral 1,541 · positive 1,524), 278–396 per person, and **23,683 one-second windows**. Sentences last 2.0–29.6 s (median 5.1 s), giving 2–29 windows (median 5).
- **Excluded:** sentences under 2 s, and person ZDN blocks 4–5 (no eye-tracking file).

**Caveat:** ZuCo labels the **sentiment of the text**, not an emotion felt by the reader. This is an adaptation, not a replication of the paper (which used emotion-inducing film clips).

## 5. Defects found on real data and fixed

These problems were invisible on the earlier synthetic data. Every fix applies **identically to all models**, and each was chosen from feature or training diagnostics, **never by looking at test accuracy**.

| # | Problem | Evidence | Fix |
|---|---|---|---|
| 1 | Paper's entropy settings (m=5, τ=2) don't work on 1-s windows | SampEn found no matches and returned a constant in 57% / 72% / 94% of alpha / beta / gamma windows | m=3, τ=1; SampEn m=2. Now 0% |
| 2 | Flat reference channel picked as a feature | Cz is the EGI reference (SD = 0). mRMR chose its constant features in almost every fold | mRMR skips constant features; Cz dropped |
| 3 | GA collapsed to one rule | Accuracy + coverage fitness was maximised by a 1–2 rule base that always said "neutral" (34.8% = the neutral share) | GA fitness uses balanced accuracy |
| 4 | Smallest class got no rules | Wang–Mendel gave 26 of 27 cells to neutral/positive, so "negative" (31%) was never predicted | Class-balanced training weights (× gate weights) |
| 5 | M1 v1 was nearly a copy of M0 | Scaling within 2–11-window sentences pushed 61% of weights to 0.1 or 1.0, correlation 0.81 with M0 | M1 scales per person, correlation 0.28 with M0 |
| 6 | Old M2 code: baseline had no effect | Subtracting each person's median was cancelled by later per-sentence rescaling | M2 rewritten with per-person scaling and per-person breakpoints |
| 7 | One file skipped | ZMG block 1 is MATLAB v5, not v7.3/HDF5 | Fallback reader |
| 8 | Downloads very slow | ~0.2 MB/s sequential | 6 parallel downloads, ~6 MB/s |

Early numbers shown before these fixes (a 1-person pilot at 35–38%, a 5-person run at ~35%) were **inflated by defects 2–4** and should not be used.

**Gate behaviour after the fixes** (share of weights at exactly 0.1 or 1.0; correlation with M0 and with M1):

| Gate | Mean weight | At extremes | Corr. with M0 | Corr. with M1 |
|---|---|---|---|---|
| M0 hard | 0.43 | 100% | 1.00 | 0.28 |
| M1 v1 (per sentence) | 0.53 | 61% | 0.81 | 0.33 |
| M1 fuzzy | 0.51 | 41% | 0.28 | 1.00 |
| M2 adaptive temporal | 0.53 | 24% | 0.19 | 0.92 |
| M2 adaptive-only | 0.53 | 40% | 0.31 | 0.94 |
| M2 causal | 0.54 | 31% | 0.24 | 0.92 |
| M1 + temporal | 0.51 | 26% | 0.17 | 0.97 |

M2 and M1 + temporal are genuinely different from M0, but very close to M1.

## 6. Evaluation

- **5-fold:** stratified 5-fold cross-validation over sentences (a sentence is never split across train and test).
- **LOSO:** leave-one-subject-out, 12 folds; each person is tested on a model that never saw them.
- **Repetitions:** 3 seeds × 5 bands × 2 protocols for every model; 240 runs in total.
- **Leakage control:** every label-dependent step (feature selection, rules, GA, gate-feature choice) is fitted on training folds only.
- **Metrics:** sentence-level accuracy, balanced accuracy and macro-F1.
- **Tests:**
  - binomial test against chance,
  - exact McNemar test between two models on the same sentences,
  - Wilcoxon signed-rank test across the 12 people (LOSO).

### 7.3 Sanity checks

- **The classifiers now behave properly.** They predict all three classes in roughly their true proportions (for example, M1 under LOSO: 34.6 / 33.0 / 32.3%, against true shares of 30.8 / 34.8 / 34.4%) and keep 12–14 rules. Before the fixes they predicted "neutral" for most sentences with 1–2 rules.
- **The data's ceiling is low.** A strong non-fuzzy model, L2 logistic regression on sentence-mean features, gets:

| Features | 5-fold | LOSO |
|---|---|---|
| EEG entropies (380 features) | 35.2% | 34.9% |
| Eye features (8) | 33.4% | 34.2% |
| EEG + eye | 35.2% | 35.5% |

So the best achievable accuracy on ZuCo with these features is about **35%**, only about 2 points above chance.

## 8. Conclusions

1. **On ZuCo, every gate ties with M0.** M1, M2 and M1 + temporal are slightly ahead under 5-fold cross-validation (+0.2 to +0.5 points) and slightly behind on unseen people (−0.2 to −0.6). Nothing is significant overall. **M1 + temporal is the most consistent** (ahead in 13/15 5-fold runs, smallest LOSO loss). Temporal smoothing on M1's fixed gate held up better than M2's per-person adaptive breakpoints.
2. **No model decodes text sentiment here,** including a strong logistic-regression baseline, which reaches only about 35%. A gate can only help when some windows carry more class information than others; on ZuCo, no window carries meaningful sentiment information.
3. **Why ZuCo cannot test the method:**
   - **Labels:** they describe the text's sentiment, not the reader's emotion.
   - **Short trials:** 2–30 s sentences against minutes-long emotion clips.
   - **Pupil size during reading** reflects gaze position, brightness and reading effort rather than emotional arousal.
   - **EEG during reading** is dominated by language processing and eye movements.
4. **What the project does deliver:**
   - a pipeline verified end to end on real EEG and eye-tracking data;
   - eight defects found and fixed;
   - three new gating methods implemented, tested and evaluated without leakage;
   - an honest negative result on ZuCo.

### Next steps

1. **Get the SEED-IV licence** (MAHNOB-HCI also works) and rerun the same pipeline with the paper's 4-s windows, entropy settings (m=5, τ=2) and 62 channels. This is the real test of M1, M2 and M1 + temporal.
2. Optionally, test the gates on a ZuCo target that EEG and eye tracking **do** encode, such as normal reading versus task-specific reading (ZuCo tasks 2 and 3). This would test the gating idea where there is signal to find.
3. If gate parameters are ever tuned, do it with nested cross-validation on training folds only, decided before looking at test results.

### Reproduce

```bash
pip install -r requirements.txt
python scripts/download_zuco.py --out data/zuco --jobs 6                      # ~20 min, 5.97 GB
python -m gfer.zuco --src data/zuco --out data/zuco_npz                        # ~2 min
python -m gfer.compare --datasets data/zuco_npz --protocols trial,loso --seeds 0,1,2 \
       --variants none,hard,fuzzy,fuzzy_trialnorm --out results/zuco_final_m0m1
python -m gfer.compare --datasets data/zuco_npz --protocols trial,loso --seeds 0,1,2 \
       --variants adaptive,adaptive_nosmooth,adaptive_causal --out results/zuco_m2/m2_only
python -m gfer.compare --datasets data/zuco_npz --protocols trial,loso --seeds 0,1,2 \
       --variants fuzzy_smooth --out results/zuco_combo/combo_only
python -m gfer.summarize --raw results/zuco_final_m0m1/raw.json --data data/zuco_npz
python manuscript/zuco_report/make_figures.py                                  # figures + stats.json
```

**Runtime:** feature extraction takes about 30 s per person; each comparison takes about 1–1.5 h on 8 cores. On a laptop on battery with Low Power Mode on, runs are 3–4× slower. Keep the lid open.
